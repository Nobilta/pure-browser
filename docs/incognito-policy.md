# 无痕模式设计契约

无痕保持普通浏览的功能与交互，使用不同的 UI 标识；差异集中在数据归属、自动记录和会话清理。
用户明确保存的成果与偏好可以持久保留，浏览过程产生的私密数据属于独立会话，退出时清理。
“数据存到了磁盘”不等于用户选择持久保存：Cookie、网站存储等即使由 WebView 写入 Profile，仍是待清理的会话数据。
这是项目的既定产品设计。修复缺陷、审查隐私或简化代码时均须保持；设计变更需要用户明确提出，不能根据其他浏览器的默认行为自行推导。

| 数据或行为 | 普通与无痕之间的关系 | 无痕会话结束后的处理 |
|---|---|---|
| Cookie、网站存储、网页登录态、页面与标签运行状态、脚本 GM 值 | 按环境隔离；无痕不继承普通登录凭据或脚本值 | 清理私密会话的数据，新会话重新开始 |
| 浏览历史 | 无痕不新增访问记录；可以读取已有普通历史作为地址栏建议 | 不把私密访问补写到历史中 |
| 网站权限、外部应用授权、临时证书例外 | 授权属于环境；进入无痕时站点设置可继承已有拒绝项，但允许项重新询问 | 丢弃私密授权，不回写或撤销普通环境的权限 |
| 书签、桌面快捷方式、安装的脚本与过滤规则、用户主动保存的设置 | 共享用户明确保存的内容 | 保留；书签或快捷方式中用户主动保存的网址也属于该内容 |
| 站点显示偏好，如桌面模式、字号、镜像和画面比例 | 用户明确修改后在两种模式共享，网站权限仍独立 | 保留最新共享值，不用无痕旧快照覆盖导入或其他修改后的值 |
| 下载记录与已保存文件 | 使用相同的确认、保存、管理流程；记录可以共享查看，传输凭据仍归原环境 | 保留记录与文件；来源和恢复能力遵循下方下载约定 |
| 分享、拍照上传等临时文件 | 按会话管理；用户已交付给其他应用的内容属于主动导出 | 清理会话临时文件；已交付的分享缓存按现有启动回收策略处理，外部副本不受浏览器清理控制 |

无痕会话内继续支持用户脚本、多标签驻留、前进后退缓存、阅读、翻译、下载、书签、分享、
增强播放器、画中画和用户开启的后台播放。锁屏、切到后台本身不等于退出无痕，Activity 重建也不应开启新会话；
退出无痕时释放所属页面与媒体，冷启动不恢复旧私密会话。无痕开关偏好可以保留，下一次启动使用新的会话身份。

**下载的退出边界：**

- 同一无痕会话内按普通规则下载、暂停、继续和重新下载，使用该私密任务的凭据，不借用普通 Cookie。
- `endPrivateScope()` 保留记录、状态和保存位置；已接受的传输允许继续完成。退出不能通过批量 `cancel()` 删除记录或中断这些传输。
- 退出后旧记录的 `canResume=false`；禁止跨会话继续、重试或重新下载，新会话也不把旧私密记录当作重复请求。已完成文件仍可打开或删除。
- 私密记录不持久化来源 URL、Referer 或 Cookie；页面文件只保留不可请求的类型占位标记。文件名、状态和实际保存位置可以保留，通知使用通用文案。
- 已停止任务在退出时清理临时数据；活跃任务等待 writer 结束后，再清理临时文件、内存播放清单和请求上下文。
  已接受的 HLS 自动重试可能继续使用 `privatePlaylists`，不能提前清空而迫使一次性播放清单重新请求。

完整隔离依赖 WebView 的独立 Profile 能力；旧 Provider 的共享存储路径须明确显示限制，退出清理可能影响普通 Cookie。
不能把该兼容路径描述成完整隔离，也不能在独立 Profile 读取失败时静默改读普通 Cookie。
现有无痕 HTTP 缓存策略保持 `LOAD_NO_CACHE`；调整它需验证 Profile 缓存的清理边界，不能仅因追求行为一致就删除。
独立 Profile 的清理可能异步完成，因此不承诺任何数据从未落盘；清理失败必须可见并遵循现有清理等待机制。

实现优先复用普通流程，只在现有会话归属、持久化和清理入口表达差异。保留真实外部边界的错误处理，
不为假设性风险增加重复校验、吞错、额外状态层或默认禁用功能。若当前实现偏离本契约，应修实现，不能修改契约或旧测试来迁就错误行为。
回归要求见[测试指南](testing.md#incognito-regression-contract)，用户可见限制见[功能介绍](features.md#无痕模式)。
