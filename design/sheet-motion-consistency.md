# 弹层与二级页面动效（已实现）

统一目标：所有"打开一个面板"的动作共用一套节奏——进入是表面整体上滑、窗口内换页是内容轻量位移、换容器是表面交替。
实现位于 `ui/shell/BrowserMotion.kt` 与 `ui/shell/BrowserSheetWindow.kt`。

## 为什么原来不一致

所有弹层本来就在**同一个 Dialog 窗口**里（`BrowserSheetHost` 整条路由存续期间只创建一个 `BrowserSheetWindow`），
但动效由各容器自己决定，于是出现三套：

| 入口 | 原容器 | 原动效 |
|---|---|---|
| 工具栏打开菜单、标签页管理 | `BrowserBottomSheet` | 表面 240ms 上滑，遮罩独立淡入 0.32 |
| 工具栏打开扫码 | `BrowserFullscreenSheet` | 无滑动，内容 120ms 淡入 + 12dp |
| 菜单内进入标签/历史/下载/开发工具/网站设置 | `BrowserBottomSheet` | 表面与遮罩不动，内容 240ms 淡入、无位移 |
| 菜单内进入设置/书签/扫码 | `BrowserFullscreenSheet` | 整块表面瞬变，内容 120ms 淡入 + 12dp |

根因是 `LocalSheetFirstPresentation` 只有"是否首次"两态，而内容过渡参数又由两个容器各写一份。

## 现在的三种语义

`SheetScene` 由"是否首次呈现 + 上一个表面是否同一种容器"推出，两个容器共用同一个入口实现：

| 场景 | 判定 | 表面 | 内容 | 遮罩 |
|---|---|---|---|---|
| `ENTER` | 窗口内首次呈现 | 上滑 `(1-p)×高度`，**240ms** | alpha 1 | 0 → 0.32，随表面淡入 |
| `WITHIN` | 同容器换目的地 | 不动 | alpha `p`，位移 `(1-p)×12dp×方向`，**120ms** | 保持 0.32 |
| `CONTAINER` | 底部面板 ↔ 全屏页 | 上滑 `(1-p)×高度`，**120ms** | 同上 | 保持 0.32 |

- **统一进入**：全屏页现在和底部面板一样整块上滑进场，背后的网页由同时淡入的遮罩压住，不会直接闪出。
- **统一窗口内换页**：底部面板的子页不再是无位移的 240ms 淡入，改为与全屏页一致的 120ms + 12dp。
- **方向感知**：`LocalSheetDepth` 由路由栈给出（1 = 顶层，2 = 菜单子页），到达页的位移方向随之决定——
  子页从下方进入、父页从上方返回，前进/后退有了方向感。
- **换容器不再瞬变**：`CONTAINER` 场景下，本页绘制一份**被替换表面的淡出副本**
  （`ReplacedSurface`：全屏页画满屏矩形，底部面板按上次实测高度画底部圆角矩形，颜色取被替换容器的实际颜色），
  与上滑进场的表面交叉 120ms，覆盖整个替换过程。
- **关闭**沿用窗口关闭行为，没有新增退出动画（与改动前一致）。

## 实现要点

- `SheetShape`（是否全屏、高度、容器颜色）在每次布局后由当前页回填到窗口状态；
  下一个路由在组合时读取它，因此能知道"我替换的是哪种容器、多高、什么颜色"。
- `SheetPresentation` 在 `LocalSheetWindow` 被清空**之前**捕获这些信息——选择器之类的嵌套弹层会拿到自己的窗口，
  所以不能事后回读。
- 动效进度用 `Animatable.asState()`，只在 `graphicsLayer`/`drawBehind` 的 lambda 里读取，不触发逐帧重组。
- 路径 key 变化会重建弹层子树，每次换页自然得到一次新的 0f→1f 动画；父页的滚动与分类状态仍由
  `rememberSaveableStateHolder` 恢复，不因动画改变。
- 遮罩仍是"不透明表面 + 独立遮罩"：任何一帧里至少有一层不透明内容在遮罩之上，网页不会被透出。

## 验证

- 回归阶段：改动后 `menu-navigation`（25 项菜单子页与返回路径、24 轮快速往返、退出确认复位）与
  `settings-back`（六个分类、选项、管理弹层、横屏两栏、左右边缘手势）在**最终交付包**上通过；
  `resident` 与 `profiles` 同批通过。
- 目视逐帧核对：在设备端把"点击 + 连续 `screencap`"放进同一条 shell 命令，抓过渡中的画面，
  四条路径都检查了起始帧与稳定帧：
  - **ENTER**（工具栏 → 菜单）：起始帧为遮罩渐入 + 表面上滑，稳定帧为不透明面板、网页被 0.32 遮罩压住；
  - **WITHIN**（菜单 → 历史）：中间帧显示表面不动、内容正在淡入（此刻 alpha≈0 时看到的是空表面），稳定帧正确；
  - **CONTAINER 正向**（菜单 → 设置）：起始帧是"被替换的菜单表面淡出 + 遮罩"，没有露出网页；下一帧全屏设置页就位；
  - **CONTAINER 反向**（设置 → 返回 → 菜单）：起始帧是设置全屏表面的淡出副本（满屏、无内容），
    下一帧菜单面板升回并稳定。
- 未做的检查：帧级时长核对（240ms / 120ms）。本机没有 ffmpeg 一类可抽帧的工具，
  `screencap` 的间隔约 150–300ms，只能确认"过渡存在且无网页闪出"，不能确认精确时长与曲线。
  需要时在带 ffmpeg 的机器上用 `adb shell screenrecord` 录制后逐帧比对。

已知特性（与改动前一致）：WITHIN 换页时面板高度会随目标页内容瞬时变化，不额外做高度动画。
