# 弹层与页面过渡

菜单、标签管理、设置、书签和扫码共用一套过渡规则。
入口实现位于 [BrowserMotion.kt](../app/src/main/java/com/mybrowser/ui/shell/BrowserMotion.kt) 和
[BrowserSheetWindow.kt](../app/src/main/java/com/mybrowser/ui/shell/BrowserSheetWindow.kt)；
路由与返回规则见[菜单导航设计](menu-navigation-20260910.md)。

## 三种过渡

`SheetScene` 根据是否首次显示、前后容器类型选择动画。下表的 `p` 表示从 0 到 1 的动画进度：

| 场景 | 容器表面 | 页面内容 | 遮罩 |
|---|---|---|---|
| 首次进入 `ENTER` | 240ms，从自身高度下方滑入 | 随表面移动，保持不透明 | 透明度从 0 到 0.32 |
| 同容器换页 `WITHIN` | 保持位置 | 120ms 淡入，并移动 12dp | 保持 0.32 |
| 底部面板与全屏页互换 `CONTAINER` | 旧表面淡出，新表面在 120ms 内滑入 | 同时淡入并移动 12dp | 保持 0.32 |

路由深度决定内容移动方向：菜单子页从下方进入，返回父页时从上方进入。
关闭沿用窗口关闭行为，没有额外的退出动画。系统关闭动画时，页面仍可正常操作。
同容器换页的面板高度直接随内容变化，没有高度补间动画。

## 实现方式

整个菜单路径使用一个 Dialog 窗口，换页时替换内容。
此前底部面板和全屏页分别定义动效，导致相同的“打开页面”操作有不同节奏；
现在两个容器通过 `SheetPresentation` 和 `sheetMotion` 选择同一组参数。

`SheetShape` 记录上一个表面的类型、高度和颜色。切换容器时，`ReplacedSurface` 绘制这份表面的空白副本，
让它随新表面滑入而淡出。副本不包含旧页面控件，也不会保留其点击或返回处理。

动画进度主要在 `graphicsLayer` 和 `drawBehind` 中读取，以减少布局工作。
目前传给 `ReplacedSurface` 的透明度仍在组合阶段读取，因此不能把整个过渡描述为“没有逐帧重组”。

路由 key 变化会重建页面子树并启动新动画；父页滚动和分类状态由 `rememberSaveableStateHolder` 恢复。
`SheetPresentation` 在清空当前窗口的 CompositionLocal 之前捕获状态，嵌套选择器因此可以使用独立窗口。

遮罩在换页期间保持，但旧表面会逐渐透明，新表面仍在移动。
这套实现不保证每一帧的每个区域都有不透明表面覆盖；是否出现可见闪烁需要通过录像检查。

## 验证方法与已有结果

`menu-navigation` 和 `settings-back` 检查页面切换、返回、窗口释放及操作可用性。
默认压力循环分别为 8 轮和 4 轮，也可以显式增加。不同安装包的阶段结果见[回归报告](../EMULATOR_TEST_REPORT.md)。

动效检查应覆盖四条路径：

1. 工具栏 → 菜单：首次进入。
2. 菜单 → 历史：同容器切换。
3. 菜单 → 设置：底部面板进入全屏页。
4. 设置 → 菜单：全屏页返回底部面板。

已有检查使用设备端连续 `screencap`，在采到的起始、中间和稳定帧中观察到了相应过渡。
采样间隔约 150–300ms，大于部分动画时长，无法证明整个过渡没有闪帧，也没有验证精确时长和曲线。
需要检查这些细节时，应使用 `adb shell screenrecord` 录像并逐帧分析。
