# 0.5.0：浏览器能力复查与 Rust 改造

本文件记录 0.5.0 对 Android 浏览器生产代码、Rust workspace、网页脚本、资源、构建和回归
脚本的复查。0.5.1 的菜单修复见 [菜单导航设计](menu-navigation-20260910.md)，当前分层和
构建清理已合并到 [架构说明](../ARCHITECTURE_REVIEW.md)。源码统一在 master 维护。

## 能力对照与已完成实现

对照 Android 浏览器常见流程检查功能完整性，参考 Chrome 的
[网站权限说明](https://support.google.com/chrome/answer/114662?hl=en&co=GENIE.Platform%3DAndroid) 和
[打印网页说明](https://support.google.com/chrome/answer/7343019?hl=en&co=GENIE.Platform%3DAndroid)。
这里比较用户任务，不将桌面扩展或账号服务直接等同于 WebView 能力。

| 用户任务 | 0.4.1 的缺口 | 0.5.0 实现与边界 |
|---|---|---|
| 修复单个站点的兼容问题 | 全局开关影响全部网站 | 网站设置管理过滤、JavaScript、图片、第三方 Cookie、桌面 UA、文字缩放；按协议、主机、端口隔离，默认端口归一化；支持站点列表、搜索和重置 |
| 网站访问相机、麦克风与定位 | 系统权限与网站同意未独立管理 | 每个 origin 的询问/允许/阻止；网站同意后再申请 Android 权限；仅安全来源或 loopback；导航取消旧请求，迟到回执不能授权新页面 |
| 误关标签恢复 | 依赖查历史，缺少直接撤销 | 关闭后 Snackbar 撤销；最多 20 条最近关闭记录，支持搜索、恢复、清空和重启恢复；清历史同时清除记录和撤销提示 |
| 在浏览器间迁移书签 | 缺少导入导出 | SAF 选择 UTF-8 Netscape HTML，预览再确认；Rust 有界解析；SQLite 单事务、重复保留旧 ID/标题；导出先验证完整内容再创建目标文件 |
| 专注阅读与离线阅读 | 缺少原生阅读视图 | 提取主 article/main 的纯文本；原生阅读、文字缩放、复制、打开原网页、显式离线保存和删除；保存的文章不执行网页代码 |
| 输出网页 | 缺少打印入口 | 接入 Android PrintManager，系统打印和保存 PDF；页面加载完成后提供入口 |
| 下载中断 | 丢失已下载字节，只能重新下载 | 保留分段和校验元数据，支持暂停、继续和进程恢复；强 ETag 或合规 Last-Modified、长度及最终实体 URL 一致才复用字节 |
| 投屏后操作播放 | 发送成功无法代表设备正在播放 | 查询远端状态；提供播放、暂停、停止、进度和音量；可见时轮询、后台停止；状态未知与设备报告播放分开呈现 |
| 退出与系统选择器 | 文件选择器期间进程被结束后，退出可能只关当前 Activity，留下最近任务和旧选择器 | 按当前 taskId 关闭本应用任务，覆盖其旧系统选择器；无法取得 AppTask 时回退平台 Activity 退出 |
| 外部链接和页面遮挡 | 开发工具打开时接收链接，新网页仍被工具面板遮住 | 接收 VIEW / SEND 网址关闭开发工具并显示目标网页；仅切回应用保留当前面板 |
| 连续进入全屏 | 新全屏视图可能读到上一轮退出前的缓存标记 | 等待新的全屏状态再接管；后台恢复后补跑连续 Blob 全屏进出 |
| 大字体与横屏 | 固定说明压缩滚动空间，Android 10 阅读弹窗缺失系统栏边距 | 将站点来源与说明纳入滚动区，底部取消/保存保持可达且等高；阅读窗口铺满屏幕、读取主窗口安全边距，校验操作及正文滚动区边界，补齐读屏名称、标题去重与系统栏主题 |

无痕不写最近关闭记录。无痕网站设置仅保存在当次内存，普通模式的 ALLOW 在无痕降为 ASK，
BLOCK 保留。显式保存书签、文章和下载文件仍是持久用户数据。WebView Profile 支持及降级清理
边界沿用 [README](../README.md)，不能将关闭历史记录宣称为完整存储隔离。

## 逐模块语言决策

| 代码范围 | 本轮决策 | 依据 |
|---|---|---|
| Rust 网络规则解析/匹配 | 保留 0.4.1 的索引与单次 DP | 已有等价性测试和长 URL 基准；本轮不重复改写 |
| 元素隐藏规则 | 从 Kotlin 迁到 `rust/adblock/src/cosmetic.rs` | 批量字符串规则和高频域名选择适合共享不可变索引；实测冷查询改善，输出一致 |
| Netscape HTML 书签解析 | 实现在现有 `url_utils` native 库 | 8 MiB 批量输入采用有界线性扫描，统一实体解码、注释/script/style 跳过与 HTTP(S) 校验；没有增加第三个产品 JNI 库 |
| URL/搜索分类 | 继续现有 Rust 快速路径和 Kotlin 回退 | 已形成稳定接口；无新热点证据 |
| Compose、设置、首页、书签/历史分页 | 保持 Kotlin 和 Android SQLite | 渲染、输入、数据库事务、图片解码均由成熟平台组件负责；复制到 Rust 会新增数据转换和生命周期边界 |
| 下载、文件名、SAF、MediaStore、通知 | 保持 Kotlin 协程与 Android API | 主要等待网络与磁盘；收益来自校验、保留字节和状态并发治理；另引 Rust HTTP/TLS 无端到端收益依据 |
| WebView、权限、隐私、安全状态 | 保持 Android 实现 | 依赖 ActivityResult、系统权限、Profile、导航及 renderer 生命周期 |
| 视频探针、用户脚本、阅读提取 | 保持网页 JavaScript | 必须访问 DOM 和网站播放器；把整页跨 JNI 复制不能替代浏览器渲染器 |
| DLNA、SSDP、SOAP | 保持 Kotlin | 有界网络/XML 数据、低频动作；主要问题是状态机、设备能力和迟到响应，无计算瓶颈证据 |
| 旧 cache/downloader/filename_parser/database | 0.5.1 已删除 | 无产品或测试调用，连同 Kotlin 门面和可选构建开关删除；实际下载文件名解析保留 Kotlin 实现 |

## Rust 实测

0.5.0 迁移时提取原 Kotlin 实现，使用同一组完整内置列表进行对照。
30,692 条元素隐藏规则，80 个 host 的生成 CSS 逐字节一致；480 个冷查询样本与 200 个重复查询样本。

| 主机查询中位数 | 原 Kotlin | 当前 Rust |
|---|---:|---:|
| 冷查询 | 1,406,458 ns | 400,667 ns |
| 同站点重复查询 | 1,360,667 ns | 167 ns（命中缓存） |

冷查询约为原耗时的 28.5%。首次 Rust 草稿曾因重复散列 selector 而更慢，最终通过加载期
selector ID 去重、布尔标记及域名后缀索引改善。LRU 限制 32 个 host、8 MiB，总 CSS 输出限制
2 MiB。表中不含 JNI 字符串复制、DOM 注入、页面加载、手机功耗，重复查询的缓存命中数字
不能换算为浏览器整体提速。书签解析没有做跨语言性能对照，不对它宣称性能倍数。

上述数字为迁移时的历史对照记录，旧源码副本和原始产物已清理。
`python3 validation/cosmetic-benchmark.py` 现在仅测量当前 Rust 实现，不依赖备份分支；
使用相同的 80 个 host，保存输入/输出哈希及冷/热查询时间到
`validation/results/cosmetic-benchmark/result.json`，不再生成旧 Kotlin 构建。

## 并发、状态和数据一致性

- 普通站点偏好与离线文章仓库由 Application 单实例持有，共用写锁；写入成功后才发布快照。
- 过滤规则在后台生成完整网络/CSS 引擎，原子切换；旧页面的 CSS 回执带页面代次校验。
- 网站权限回调只处理一次；同意、系统回执、导航取消、私密切换都按当前请求身份处理。
  WebView 定位回调不另行永久记忆，避免绕过应用内撤销。
- 下载每个任务使用跨 Job 替换仍有效的 Mutex；暂停/继续不能让最老的 writer 与新任务同时写入。
  取消和删除等写入结束后清理临时文件，完成后才发布 MediaStore/SAF 目标。
- 续传同时校验 validator、长度和重定向后的实体 URL；不满足时完整重新下载。
  拒绝异常 206、错误范围/长度和压缩实体；下载元数据不保存 Cookie，普通重试重新读取当前 Cookie。
- 用户主动暂停不会自动开始；普通模式中运行时被杀的任务回前台后尝试恢复；私密任务不自动恢复。
- DLNA 动作与状态查询串行并校验会话代次；没有 RenderingControl 或可靠进度信息就不显示对应控件。

## 验证及真实限制

自动检查、最终签名包哈希、两版 Android 的逐阶段结果以
[README](../README.md) 和 [模拟器报告](../EMULATOR_TEST_REPORT.md) 为准。Android 主机测试会实际
加载测试用 Rust JNI，新增 host native 输出不会进入 APK。书签、下载、权限、标签、阅读和
打印均有可重放夹具；同一设备上的 UI 操作串行运行。

离线文章限 50 篇/8 MiB，单篇最多 600 块/150,000 字符，仅保存文字；书签导入限 5,000 条/8 MiB，
文件夹展开；过滤仅支持已声明语法子集。DLNA 已做本地 SOAP/状态测试，没有实体电视，
因此不声称实体设备播放与厂商兼容已经验证。

自有账号同步、加密密码库、完整 WebExtension/Tampermonkey 环境、Google Cast、独立渲染/解码引擎、
完整网页归档和内置翻译目前仍未实现。这些依赖独立的服务、密钥/同步设计或新的引擎集成，
不能以占位 UI 视为补齐；后续应按 [剩余工作](follow-up-priorities.md) 验收。
