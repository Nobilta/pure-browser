# 菜单返回与弹层生命周期（0.7.2）

## 当前导航规则

菜单只能进入一个子页面：设置、书签、历史、下载、网站设置、开发工具或媒体选择。
设置内部的路径为“选项 → 分类 → 设置首页 → 菜单 → 浏览器”。左上角、系统返回和边缘手势使用同一规则。
工具栏直接打开的标签、投屏和倍速没有菜单父级。打开网页、切换模式或应用倍速关闭整条菜单路径。
普通后台切回保留当前界面，外部 VIEW/SEND 网址清空临时导航，配置重建保存当前来路。

菜单已移除分享网页、复制链接和打印/PDF，开发者工具仍只有菜单入口。

## 窗口与回调的所有权

- `BrowserSheetNavigation` 原子保存路由和当前 `Presentation`。仅 MENU 可以压入一个子页面，
  恢复时拒绝反向父子关系、三层路径、重复目的地和无效 key。
- 路由 key 恢复滚动与分类；每次显示创建新的 `Presentation`。迟到关闭回调和重复点击
  只能操作原页面，不能关闭后来显示的页面，返回父级也会更换回调身份。
- `BrowserSheetHost` 只挂载栈顶，父级只保存 UI 状态，路由 key 隔离各页面组合。
  菜单滚动状态置于 Dialog 自身的保存注册表之外，以便返回时恢复。
- 设置使用独立全屏 `Dialog`，由它的关闭请求处理设置内部返回，移除了 Activity 级的设置 `BackHandler`。
  画面、触摸和系统返回属于同一个窗口；退出设置时整窗释放，不再把设置 Surface 留在 Activity 中。
  菜单返回后同时检查窗口数量与所有窗口的内容，避免只检查路由模型而漏掉残留界面。
- 选项和管理弹层打开时停用设置父级返回。选项使用代次标识，旧关闭回调不能清除新选项。
- 菜单使用主窗口安全边距，拖动手柄不会覆盖系统状态栏；设置全屏窗口显式同步主题与安全边距。
- 浏览器退出确认使用单调时钟。菜单操作清除此前退出计时，只有浏览器本身连续两次返回才能退出。

0.7.1 在本地 Android 17 的单次真实手势序列中没有重现“设置反复出现并卡住”的全部现象。
本版针对设置画面和 Activity 返回处理分离的路径改为窗口统一持有，并用重复返回、窗口销毁、
左上角按钮和实际网页触摸验收；不将该现象断言为已复现的 ANR。

## 网站设置滚动

网站表单与管理列表仍使用底部弹层，关闭 `sheetGesturesEnabled`、拖动手柄和内容 overscroll。
列表滚动到顶部或底部时，不再把剩余拖动传给弹层，也不再拉伸表单画面。
标题和操作栏保持固定位置，表单使用取消/系统返回关闭，管理列表补充左上角返回。

旧包在网站表单顶部下拉可把整个弹层带走；新版验证上下边界的连续快/慢滑动，
并比较停止后的真实像素，不能只根据无障碍树中坐标不变认定动画停止。

## 可重复验证

- 单元测试验证父子返回、迟到回调、重复点击、整条路径关闭、直接入口、重建与退出确认。
- `menu-navigation-regression.py` 验证系统与工具栏返回、24 轮快速返回、0/15/50/100 ms 立即返回、
  后台切回、重建、菜单拖动、窗口数量以及返回后实际网页触摸。
- `settings-back-regression.py` 验证六个分类、选项、管理弹层、横屏两栏、重建，以及左右边缘手势
  和左上角返回的六轮交替往返。退出后所有窗口中均不能留下设置内容。
- `capabilities-regression.py --section site` 验证每个边界六次快/慢滑动，标题和保存按钮不移动，
  停止后三次原始截图中的表单像素相同，并继续验证修改、取消、保存和网站设置生效。

```bash
python3 validation/qa-server.py --apk PureBrowser-v0.7.2-release.apk
python3 validation/setup-ui-probe.py emulator-5554
python3 validation/run-regressions.py --serial emulator-5554 --apk PureBrowser-v0.7.2-release.apk \
  --label release-072-navigation --stages menu-navigation settings-back site layout
```

实际安装包、设备与失败记录以 README 和 EMULATOR_TEST_REPORT 为准。输入没有回执时失败，
不自动重放可能已经送达的返回；临时测试文件在完成后删除。
