# 菜单返回与弹层生命周期修复（0.5.1）

## 已确认的问题

0.5.0 用单个 `Sheet?` 同时表示菜单、设置、书签等页面。进入子页面时直接覆盖 `MENU`，
关闭子页面时设置为 `null`，因此没有可返回的菜单父级。Android 14 上的旧签名包实测：
打开菜单后直接返回正常；设置首页返回后已经显示网页，后续返回会进入网页历史或退出确认。

原设置测试只断言“菜单”文字存在，浏览器工具栏的菜单按钮也满足这个条件，因而漏掉了完整链路。
新的测试要求实际菜单面板、正确的前台 Activity 和窗口数量，旧包在“设置 → 菜单”处失败。
旧包验证时的 APK SHA-256 为
`3b54543e8f36755ca9b283a65b18fa32d542d3f9a6032a149595cad273204392`。
旧包和旧基线原始文件已清理，保留此处的复现结论及新版回归脚本。

当前实际使用 Material3 1.3.0、Compose UI 1.9.2。Material3 的关闭动画通过
`invokeOnCompletion` 调用 `onDismissRequest`，取消动画也可能执行完成回调。
原有回调无条件清空 `sheet`，无法区分旧菜单、新页面和重新打开的菜单。
这确实存在状态竞态；用户报告的那一次“卡死”没有设备日志，不能据此认定是 ANR 或断言其唯一原因。

## 处理方式

- `BrowserSheetNavigation` 保存来路。菜单进入设置、书签、历史、下载、网站设置、离线文章和开发工具时压入子页面。
  从菜单进入投屏/倍速也保留来路，工具栏或视频控件直接打开的投屏/倍速关闭后返回网页。
- 返回只弹出当前一级；选中网页、保存并刷新网站偏好、应用倍速、分享、打印、阅读当前页等明确操作关闭整个菜单路径。
- 每次显示有独立的 `Presentation`。返回父级时也更换这个身份，迟到的关闭回调、重复点击和重复关闭不能操作新页面。
  路由的保存 key 保持稳定，用于恢复菜单滚动位置、设置分类与选项。
- `BrowserSheetHost` 只挂载栈顶页面，保存父级 UI 状态而不保留父级菜单窗口。
  菜单滚动状态移到 Dialog 外，避免进入子页面时被 Dialog 自己的状态注册表丢弃。
- 长菜单的拖动手柄原先位于系统状态栏内，实测拖动会打开通知栏。现在从主窗口读取安全边距，
  将手柄和内容放到可触摸区域内；同时适配 Android 10 的 Dialog 内边距获取差异。
- 设置分类仍按“选项 → 分类 → 设置首页”返回；设置的管理弹层打开时停用父级返回处理。
  设置选项弹层也有代次标识，过期关闭回调不能清除新打开的选项。
- 设置里的“关于 → 开发工具”返回原分类。书签编辑结束返回原列表并保留菜单来路。
- Activity 保存完整路由及 key，同进程重建保留来路；外部 VIEW/SEND 导航清空临时页面，普通后台切回保留页面。
- 退出确认使用单调时钟。打开菜单或消费菜单返回时重置计时，之前在网页上的一次返回不能沿用到关闭菜单以后。

这部分属于 Android 窗口、Compose 状态和输入事件的生命周期问题，保持 Kotlin 实现；Rust 改写不会消除这些竞态。

## 可重复验证

新增 10 项状态测试覆盖父子返回、过期菜单与子页回调、重复点击、关闭整条路径、直接入口、
重建时保存 key、无效恢复数据、100 次往返及退出确认计时。

`menu-navigation-regression.py` 使用真正的 UI 输入和窗口断言，覆盖：

- 菜单直接返回，设置经系统/工具栏返回菜单再返回浏览器，菜单滚动位置。
- 书签、历史、下载、离线文章、网站设置、开发工具的菜单来路和窗口回收。
- 关于页开发工具、设置选项、后台切换、字体引发的 Activity 重建、拖动关闭。
- 24 轮快速连续返回（30/80/160/300 ms 间隔）及点击设置后立即返回（0/15/50/100 ms）。
- 退出确认窗口内的完整输入序列，外部网址打断设置选项，最后真实点击网页链接检查触摸仍可用。

输入辅助程序返回实际注入完成回执和耗时；没有回执时失败，不自动重试可能已送达的返回事件。
UI dump 辅助进程异常与浏览器进程异常分开核对。
